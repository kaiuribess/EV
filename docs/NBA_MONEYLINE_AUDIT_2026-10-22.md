## A. Root cause

The first broken production stage is the source-to-canonical mapping. `ProviderBridge.start()` loads `data/verified_mappings.json` (`backend/evplatform/plugins/external.py:45-52`), which does not exist. `VerifiedProviderMapper.from_file()` therefore returns an empty registry, and each otherwise parsed sportsbook offer is quarantined with `Verified event/player/line/settlement mapping required` (`backend/evplatform/integrations/normalization.py:763-793,982-1004`). The production `/api/launch/setup` accurately reports zero real reference markets. This is missing reviewed configuration, not a persistence-count bug.

Separately, `NativeRuntime.start()` loads `data/launch_profile.json` or `data/launch_portfolio.json` and `data/native_mappings.json` (`backend/evplatform/core/native_runtime.py:75-116`); all three are absent. `/api/launch/setup` derives profile, native-map, reference-market and candidate counts from those runtime objects (`backend/evplatform/core/launch_setup.py:33-52,139-158,250-271`), explaining `0 / 0 / 0 / 0`. The paper workspace on port 8001 has separate settings/database and 97 real reference *observations*; its paper records do not populate the production workspace on port 8002.

Creating mapping files would not fix the current data. The 18:33 UTC bounded review found 77 exact outcome-label leads but **zero** with both current, verified quote observation and exact sportsbook market-status evidence. The NBA mainline profile is research-only: `live_execution_allowed=false`; it uses power devig with proportional sensitivity, requires two distinct books including Pinnacle or Circa, and has weights Pinnacle/Circa/BetOnline/FanDuel/DraftKings = 35/35/10/10/10. Its 5-second execution quote limit is stricter than the review's 120-second screening limit. No effective book weights, fair probability, EV, or Kelly size can honestly be computed for this game.
